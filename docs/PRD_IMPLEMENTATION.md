# PRD 一期实现与后续范围

本次迭代将问答入口升级为持续检测和事件处置工作台。需求以用户提供的 PRD 为依据；一期采用“自动检测、自动诊断、人工执行与确认”。

| 需求 | 当前实现 | 后续范围 |
| --- | --- | --- |
| F1 告警接入与降噪 | 文件增量监听、普通 Webhook、Alertmanager、5 分钟维度聚合、手工拆并、原始告警回溯 | 更多云厂商格式、复杂跨服务因果关联 |
| F2 上下文采集 | 配置式 Prometheus/Loki/变更/拓扑并行 GET 查询，故障前一小时、失败与未配置标记 | 各平台专用适配器、Trace、曲线可视化 |
| F3 ReAct 根因分析 | 本地确定性模式；可选 LLM 有界工具循环、引用校验、未知边界、模型失败降级 | 根据模型选择动态追加查询、更多观测工具及评估集 |
| F4 RAG | 25 条 Runbook、中文与错误码 BM25、来源过滤、检索层元数据过滤、结构化 JSON 导入及可信度 | PDF/Markdown 分块、Embedding、混合召回、Rerank、Wiki 同步 |
| F5 多轮诊断 | 事件内追加信息与日志、新一轮上下文采集和诊断、诊断版本持久化 | 复杂会话记忆与对话意图过滤 |
| F6 分级处置 | 查询命令与需人工审查建议标记，全部 advice_only，人工记录解决结果 | 二期白名单执行及审批流程 |
| F7 可解释与审计 | 时间戳、检查假设、动作、结果摘要、上下文来源、事件时间线与查询审计 | 审计导出、企业日志平台对接 |
| F8 知识沉淀 | Markdown 复盘初稿、区分候选根因与人工处置，人工导入经验 | 工单系统推送、复核后自动回灌 |
| F9 权限 | 本机默认访问、操作员/只读/告警令牌、异站写入拒绝、无 shell 执行通道 | SSO、按服务授权、审批沙箱与命令执行 |
| F10 看板 | 事件/告警/源健康、耗时与故障分布，真实已解决事件的 MTTR | 人工标注准确率、采纳率与趋势；无数据指标保持未知 |

## 使用边界

系统只监听已经登记且当前主机可访问的文件，不会自动发现所有服务器，也不会直接连接 Kubernetes API。集群故障可通过 Events/Pod 日志文件和告警进入相同链路；需要现有采集器提供数据。

本地置信度是日志模式及知识匹配的启发式分值，不是统计校准后的概率。故障现象与最终根因不能混同，重复相同报错不会增加独立证据。没有上下文的诊断需要现场验证，恢复检查不会以日志沉默为健康证明。

单进程 SQLite 与本地文件适用于开发、演示和小规模验证。当前未证明 99.9% 高可用或 PRD 中的 Top1/Top3 准确率目标；正式投产前应基于真实故障样本评估，拆分采集和任务队列，接入身份系统及集中审计。
